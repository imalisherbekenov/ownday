## Что должно заработать

Когда приложение выложено и адрес известен, в боте сами появляются два входа: кнопка меню
у поля ввода открывает Mini App, и на постоянной клавиатуре появляется «Открыть
приложение». Пока адреса нет — бот ведёт себя ровно как сейчас, без единого отличия.

> «Подготовить, включится сама по `APP_URL`» — решение пользователя от 23.08

## Разделы спецификации

## Осторожно

`apps/bot/src/handlers.ts` только что принят и стоит на 92 тестах. Трогай в нём **только**
то, что нужно для кнопки входа. Порядок разбора текста в `text()` — метки клавиатуры
раньше шагов мастера — переделывать нельзя ни при каких обстоятельствах: это было
отдельной находкой прошлого прохода.

## Критерии приёмки

- [ ] При заданном `APP_URL` `publishBotSetup` ставит `setChatMenuButton` типа `web_app`
      с этим адресом и подписью из словаря
- [ ] При незаданном `APP_URL` — по-прежнему `{ type: "commands" }`, поведение бота
      не отличается от нынешнего ни в чём
- [ ] На постоянной клавиатуре при заданном `APP_URL` появляется кнопка «Открыть
      приложение» с `web_app`; без него кнопки нет и раскладка прежняя
- [ ] Тип `InlineButton` в `keyboards.ts` уже допускает `web_app` — воспользоваться им,
      а не расширять заново
- [ ] Ключи новой кнопки есть в `ru.ts` и `en.ts`, паритет словарей не нарушен
      (существующий тест это проверяет)
- [ ] **Ни одна существующая кнопка бота не заменена ссылкой на приложение.** Бот остаётся
      полностью работоспособным без Mini App — это необсуждаемый принцип
- [ ] Тест: `publishBotSetup` с моком API, случай «`APP_URL` задан» — тип кнопки меню
      `web_app`
- [ ] Тест: случай «`APP_URL` не задан» — тип `commands`, кнопки на клавиатуре нет
- [ ] `apps/bot/.env.example` называет `APP_URL` с пустым значением
- [ ] Все 92 существующих теста зелёные
- [ ] `npx turbo run test typecheck build format:check --force` зелёный
