# Реализация Ownday

Выбрано оформление C — «Живой дневник». Спецификация: `ownday-implementation.md`. Ниже фактический статус; готовность к выпуску не объявлена.

## Публикация веба — 14 сентября 2026

Новая версия опубликована на https://ownday.vercel.app из основной ветки master. Реализация: 1a96f42; защита новых серверных таблиц RLS: 813d732. GitHub Actions для 813d732 завершился успешно: сборка, тесты, типы, миграции PostgreSQL и репетиция восстановления.

С явного разрешения владельца сохранён локальный JSON-снимок всех десяти исходных таблиц production вместе с описаниями столбцов, ограничений и индексов. Он восстановлен в изолированной PostgreSQL, миграции проверены на копии. В production применены десять добавочных миграций одной транзакцией через авторизованный Supabase SQL Editor; проверки контрольных сумм до и после изменений защитили исходные строки. Учёт Prisma сохранён с именами и SHA-256 исходных файлов, всего 11 миграций. Этот способ использован потому, что Vercel не раскрывает Secret-переменные для локального CLI. Все восемь новых служебных таблиц имеют RLS без клиентских политик.

Проверены главная, поддержка, приватность и вход (HTTP 200), отказ /api/sync без авторизации (401), /api/health с отдельным секретом (ready, 200). В production сохранились один аккаунт, одна привычка и одна отметка. Проверены RU/EN, темы, демо и FAQ. Снимок и отчёт находятся в игнорируемой .release-secrets; в GitHub и Vercel они не отправлялись. Это разовая копия прикладных таблиц, а не настроенная автоматическая система резервного копирования Supabase.

## 1. Надёжность данных — основная реализация проверена

Исправлены календарная граница DST, недельные/месячные квоты, индивидуальная статистика, полный годовой тренд и проверка полного дня. Архивные интервалы исключаются без изменения исходных отметок.

Операция имеет отдельный UUID, версию, журнал результата и техническую запись отмены. Авторизация предшествует чтению результата повтора. Одинаковое правило изменения отметок используется в SQLite и PostgreSQL. Секрет обязателен; ограничения запросов хранятся в PostgreSQL.

Миграции проверены в локальной PostgreSQL 16, в GitHub CI и на копии действующих данных; production обновлён 14 сентября, см. выше. Тест миграции создаёт отдельную БД с первоначальной схемой, переносит пример старой истории, проверяет сохранение идентификаторов и дробного значения. Изменения привычек, порядок и синхронизация используют общую блокировку пользователя. Удаление проверяет архив внутри транзакции: восстановленная параллельно привычка и её отметки не удаляются.

## 2. Мобильный «Живой дневник» — реализован основной цикл

Настоящая SQLite: создание/редактирование, расписания, утро/день/вечер, счётчики и минуты, дробные значения, пропуск/возврат, отмена, календарь, архив/восстановление, поиск, сортировка, статистика, RU/EN, темы и экспорт. Изменение и очередь коммитятся одной транзакцией.

16 проверок SQLite: перезапуск, откат при ошибке очереди, дробные значения, изоляция профилей, перенос гостя, повтор после потерянного ответа, история конфликтов, восстановление старых очередей, устаревшие действия виджета и удаление профиля аккаунта. В свежем Chromium проверены RU/EN, темы, длинное название, значение 2,5, пропуск/отмена и сохранение после перезагрузки на 390 и 1440 px. Форма сохраняется при высоте окна 420 px; это не заменяет реальную экранную клавиатуру.

Собраны Android APK/AAB для ARM64 и x86_64 с отдельным upload key. iOS-приложение и виджет успешно собраны Xcode в EAS для симулятора. Запуск на физических устройствах пока не проверен; подписанный IPA для iPhone ещё не получен. Календарные настройки аккаунта пока меняются через веб; настройки гостя доступны локально.

## 3. Вход и синхронизация — реализация подключена, проверка устройств остаётся

Одноразовые коды, PKCE, отзываемые сессии, фиксированный callback без токена в URL. Серверные интеграционные тесты проверяют однократность, конкуренцию, истечение и отзыв. Выход без сети сохраняет запрос отзыва и изолирует локальный профиль.

Подключены GET/POST /api/sync, передача гостевых данных, автоматические повторы и интерфейс конфликтов. Снимок сервера отделён от неподтверждённых изменений. Независимые положительные прибавления складываются; остальные конфликты сохраняют обе версии. Удалённые привычки не восстанавливаются старым клиентом.

Две настоящие SQLite-базы проверены через PostgreSQL и сериализацию JSON: конкурирующие прибавления, отмена, сохранение локальной версии 6,5, принятие серверной версии, новое действие после отмены и потеря ответа без дубля.

Старые AsyncStorage-кэш/очередь и нативные очереди виджетов v1 сохраняются. Действия принадлежащих аккаунту привычек восстанавливаются через явный выбор, без автоматической перезаписи. Чужие/удалённые привычки и некорректные действия не импортируются. Остаётся проверка обновления установленного старого приложения, нативного OAuth, истечения сессии, разных аккаунтов и больших историй. Сейчас используется полный снимок, без постраничной дельты; старый кэш не показывается как полноценный офлайн-журнал до входа.

## 4. Напоминания и виджеты — реализация подключена, устройства не проверены

Локальные уведомления: разрешения, время по привычке, ближайшие 60 событий на срок до 14 дней, обновление при открытии, отмена при смене профиля и переход к привычке. Три проверки планировщика включают DST, архив, выполненный день и ограничение числа событий.

Telegram: очередь PostgreSQL, уникальные события, аренда с токеном, SKIP LOCKED, повторные попытки и retry_after, пропуск неактуальных/выполненных привычек. Три интеграционные проверки БД и пять проверок воркера. Реальные сообщения не отправлялись. Авария после отправки до подтверждения может повторить сообщение — Telegram не поддерживает ключ идемпотентности sendMessage.

Виджеты v2: профиль, дробные значения, 31 день расписания, UUID операций, подтверждение только после SQLite, сохранение старых очередей, разбор устаревших действий с обеими версиями. Android собран с новым Kotlin. iOS получил App Group, файловую очередь с блокировкой, bridge и календарный Timeline; приложение и расширение успешно скомпилированы Xcode. Работа виджетов на устройствах остаётся непроверенной. Подробности: [ADR 0017](adr/0017-reminders-and-widget-delivery.md).

## 5. Сайт и авторизованный веб — основной перенос реализован

Сайт проверен локально на 390 и 1440 px, включая тёмную английскую версию. Выбранный язык сохраняется после обновления. Обычная главная не загружает Telegram SDK; загрузка и вход включаются при запуске из Telegram. Ссылки на магазины появятся после выпуска; сейчас показан статус подготовки. Владелец указал имя Alisher Bekenov и публичный адрес alifarlinbekenov21@gmail.com; контакты добавлены. Окончательные сроки хранения ещё нужно определить.

Веб-день и карточка привычки используют полный снимок и общий контракт операций, календарь, дробные значения, отмену и пропуск. Создание/редактирование и архивирование проверяют ревизии; шаблон открывает заполненную форму. Конфликт сохраняет исходное намерение клиента и ответ сервера в журнале, включённом в JSON-экспорт. Неподтверждённая операция переживает обновление вкладки в sessionStorage; закрытие вкладки может удалить её. Это не полноценная офлайн-база веба.

Навигация, основные экраны, формы, статистика, вход и ошибки переведены на RU/EN; тема и язык сохраняются в настройках. Удаление аккаунта вынесено из формы настроек и требует ввода DELETE. Сквозная проверка настоящего тестового аккаунта: создание, 2,5, пропуск/отмена, архив/восстановление, тема/язык, экспорт и шесть экранов на 390/1440 без переполнения и ошибок JavaScript. Реальный запуск внутри Telegram ещё не проверен. Сортировка веба пока использует прежний контракт порядка; подробное управление Telegram-напоминаниями и полный конфликтный сценарий порядка остаются.
