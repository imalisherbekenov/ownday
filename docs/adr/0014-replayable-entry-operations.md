# 0014. Изменяемые отметки и повторяемые операции

Заменяет правило first-write-wins из ADR 0012. Политика конфликтов подтверждена пользователем 13 сентября 2026 года.

Дневной факт остаётся уникальным по привычке и дате. UUID операции хранится отдельно в журнале с исходным запросом и результатом. Повтор возвращает принятый результат и не меняет более новую отметку. Проверка владельца предшествует чтению журнала.

Запись факта и квитанции выполняется одной транзакцией с блокировкой пользователя. Это также упорядочивает коммиты его последовательности изменений. Отмена оставляет техническую запись с новой ревизией; обычные выборки её скрывают. Существующие идентификаторы записей сохраняются.

Операции нового мобильного API передают исходную ревизию. Независимые положительные прибавления коммутативны. Остальные изменения требуют совпадения ревизии. Последняя некоммутативная правка задаёт границу, через которую старое прибавление автоматически не переносится. Конфликт сохраняет запрошенное изменение и текущий результат; интерфейс разрешает его отдельной новой операцией.

Старые серверные действия создают UUID непосредственно при выполнении и проходят через тот же механизм записи. Их HTTP-повтор не считается надёжным повтором клиентской операции, пока форма не передаёт свой сохранённый UUID. Старые мобильные клиенты продолжают пользоваться совместимым `habits.mark`; для гарантированного разрешения конфликтов нужен новый `habits.apply`.

Журнал новых операций не восстанавливает ранее потерянные действия. Для старых записей миграция фиксирует доступное состояние на момент перехода. Результаты операций и конфликтов удаляются вместе с владельцем или окончательно удалённой привычкой.
