# 0018. Нативный вход Apple

Статус: сервер и клиент реализованы; проверка на iOS и подключение Apple Developer ожидаются.

Expo AppleAuthentication показывает системную кнопку только на поддерживаемом iOS. Сервер выдаёт случайный nonce на пять минут, хранит только его хэш и использует отдельное назначение `apple`. После системного входа сервер проверяет JWT публичными ключами Apple: RS256, issuer, audience из APPLE_NATIVE_CLIENT_ID, nonce, exp и возраст iat. Только после проверки nonce атомарно погашается; повторная отправка не выдаёт новую сессию. Клиент сохраняет отзываемую сессию Ownday в SecureStore. Токен не передаётся через URL.

Приложение проверяет состояние Apple credential при чтении сессии, с кэшем до минуты. Отозванный credential прекращает клиентскую синхронизацию, а запрос отзыва сессии Ownday сохраняется до отправки. Это не заменяет серверные уведомления Apple об отзыве.

Идентичность определяется Apple sub, а не email. Подтверждённый email использует существующее правило связывания аккаунтов; адрес Apple Private Relay сохраняется как адрес провайдера. Полное имя не запрашивается.

## Проверено

Пять криптографических тестов: настоящая RSA-подпись, корректный nonce, отклонение неправильного audience/issuer и просроченного токена. PostgreSQL: одно из шести конкурентных погашений, истечение nonce, разделение назначений. Это не проверка реального Apple-провайдера.

## Перед iOS-релизом

Создать Apple Developer, включить Sign in with Apple для `app.ownday.mobile`, задать APPLE_NATIVE_CLIENT_ID на staging и проверить устройство. Остались серверные уведомления об отзыве и отзыв авторизации Apple при удалении аккаунта; для последнего нужен обмен authorizationCode и защищённое хранение/удаление refresh token. Текущая реализация не сохраняет Apple refresh token и не вызывает Apple revoke. До завершения этого сценария готовность iOS к магазину не подтверждается.

Источники: [Expo AppleAuthentication](https://docs.expo.dev/versions/latest/sdk/apple-authentication/), [публичные ключи Apple](https://appleid.apple.com/auth/keys).
