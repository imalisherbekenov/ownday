# 0016 — Локальная синхронизация и сохранение конфликтов

Принято пользователем: независимые положительные прибавления суммируются; абсолютные значения, отмены и архив при конфликте требуют выбора. Обе версии сохраняются.

SQLite хранит подтверждённое состояние отдельно от очереди. Видимые данные собираются из подтверждённого снимка и локальных действий. Изменение и запись очереди находятся в одной транзакции. Сетевой ответ применяется только к тому профилю, который начал отправку.

Каждая операция имеет UUID. `dependsOn` ссылается на предыдущую операцию того же объекта. Сервер проверяет владельца, объект и результат зависимости и использует подтверждённую версию. Это позволяет отправить цепочку после слияния независимых прибавлений без ложного конфликта и без потери настоящего конфликта.

Если ответ потерян, UUID не меняется. Подтверждение удаляет операцию из очереди транзакционно с записью серверного состояния. Полная загрузка не заменяет неподтверждённые действия. Автоматические попытки происходят при возвращении в приложение, после локальных изменений и периодически при открытом приложении.

При конфликте сохраняется локальное итоговое значение до ответа. Оно не пересчитывается поверх конфликтующей отмены другого устройства: 6,5 остаётся 6,5, даже если сервер теперь содержит удалённую отметку. Последующие локальные действия обновляют эту версию; отправка зависимой цепочки приостанавливается. Выбор записывает обе версии и всю цепочку в историю конфликтов, затем либо принимает серверную, либо создаёт новую абсолютную операцию с текущей подтверждённой версией. Новое конкурентное изменение снова вызывает конфликт.

Удалённая отметка передаётся как техническая запись с версией. Удалённая привычка оставляет на сервере только идентификатор и владельца, чтобы старое устройство не создало её заново. Удаление аккаунта удаляет и эти идентификаторы.

Изменённое офлайн расписание не переписывает серверную историю задним числом. В конфликте пользователь может применить своё расписание с сегодняшнего дня, сохранив исходный вариант в экспорте.

Перенос гостя копирует очередь в профиль аккаунта и сохраняет исходный профиль. После переноса создаётся новый гостевой профиль для следующего выхода. Уже перенесённый профиль нельзя автоматически импортировать повторно или в другой аккаунт.

Очереди прежнего AsyncStorage-клиента и нативных виджетов сохраняются без удаления источника. После загрузки своего аккаунта старые действия без версии попадают в разбор конфликтов. Проверяются принадлежность привычки, дата и однократность импорта; другие аккаунты эти действия не получают.

Ограничения этапа: используется полный снимок, а не постраничная дельта. Календарные настройки аккаунта изменяются в веб-версии и принимаются при загрузке; локальная тема и язык не синхронизируются. Нативный OAuth-возврат, работа на двух физических устройствах и истечение сессии в интерфейсе ещё не проверены.
