# ADR-0008. D03: SDK подключается обычным тегом в `<head>`

## Контекст

План предписывал подключить `telegram-web-app.js` через `next/script` со
`strategy="beforeInteractive"` — считалось, что этого достаточно, чтобы скрипт исполнился до
первой отрисовки и до инлайнового скрипта темы.

## Решение

Код доказал обратное: в App Router `next/script` с `beforeInteractive` тега скрипта не
выдаёт. В собранной прод-странице стоят только `<link rel=preload>` и
`(self.__next_s=…).push([…])`, а сам SDK подставляет клиентский рантайм Next уже после.
Проверено чтением выданной разметки, а не рассуждением. SDK доставляется обычным
`<script src="https://telegram.org/js/telegram-web-app.js"></script>` в `<head>` корневого
layout, синхронно.

## Почему

Инлайновый блокирующий скрипт темы стоит следом и всегда видел `window.Telegram === undefined`.
То есть тема не выставлялась ни разу — ни в dev, ни в проде, — а вместе с ней не исполнялся
и весь остальной код Telegram: это и есть источник «функция есть и сломана» вместо «функции
нет».

Рассмотрено и отвергнуто:

- **Оставить `next/script` и дождаться SDK асинхронно.** Ожидание переносит определение
  темы за первую отрисовку — вспышка чужой темы, ровно то, что запрещено.
- **Положить SDK в репозиторий и раздавать со своего домена.** Telegram обновляет его на
  своей стороне и рассчитывает на загрузку с `telegram.org`; замороженная копия отстанет от
  клиентов.
- **Инициализировать всё в `useEffect` без раннего скрипта.** Это и есть исходное состояние
  — мёртвый код, ради починки которого затеян прогон.

## Последствия

Старт страницы блокируется загрузкой стороннего домена: если `telegram.org` недоступен,
отрисовка ждёт. Обычный веб платит тот же запрос, хотя SDK ему не нужен. Инструмент
фреймворка отвергнут в пользу ручного тега, и однажды обновление Next может починить
`beforeInteractive` — возврат к нему допустим только после проверки фактически выданной
разметки, а не документации.
