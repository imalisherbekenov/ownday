# 0019. Подтверждаемое удаление аккаунта

Мобильные настройки требуют ввода DELETE перед запросом. API принимает только bearer-сессию и ожидаемый UUID аккаунта; cookie и UUID сами по себе не дают права удаления.

Удаление User и связанных серверных данных выполняется транзакционно. В этой же транзакции сохраняется подтверждение: SHA-256 сессии, SHA-256 UUID и срок семь дней. Подтверждение не содержит названий, email и истории. Оно позволяет повторить запрос после потери ответа, когда исходная сессия уже удалена. Advisory lock сериализует конкурентные повторы. Просроченное подтверждение не разрешает новую операцию.

После подтверждённого ответа SQLite одной транзакцией удаляет профиль аккаунта и гостевые профили, ранее перенесённые в него. Остальные аккаунты остаются. Приложение переключается на нового гостя. Маркер удалённого профиля позволяет подтвердить и убрать поздние действия виджета, не восстанавливая данные. Старые экспорты и сырые резервные копии прежней версии не удаляются автоматически; интерфейс сообщает об этом до подтверждения.

При недоступной сети или неподтверждённом ответе локальные данные и credential остаются для повтора. Тесты используют настоящую SQLite и отдельную PostgreSQL, включая чужой аккаунт, повтор, истечение подтверждения и позднее действие виджета.

Ограничения: требуется автоматизация очистки просроченных подтверждений и AuthGrant. Для iOS ещё нужен отзыв авторизации Apple при удалении и серверные уведомления провайдера; см. ADR 0018. Проверка этих сценариев на физическом устройстве остаётся обязательной.
