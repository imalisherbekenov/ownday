# Сборки Android и iOS

Идентификатор приложения: `app.ownday.mobile`. Новая карточка Google Play; прежних опубликованных сборок и ключей нет. Expo-проект `@nevertheless/ownday` подтверждён владельцем, доступ CLI проверен 14 сентября 2026 года.

## Android

Из корня репозитория, с JDK 17 в `JAVA_HOME` и Android SDK в `ANDROID_HOME`:

```sh
# Только один раз для нового приложения. Существующие файлы никогда не заменяются.
node scripts/android-release.mjs --init-key

# До этого последовательно выполнить установку пакетов, сборку зависимостей и native:generate.
node scripts/android-release.mjs --api-url https://ownday.vercel.app --version-code 1
```

Команда собирает APK и AAB для ARM64 и x86_64, проверяет обе подписи и совпадение сертификата с локальным upload key. Также проверяются идентификатор, номер версии, фактические архитектуры, отсутствие debug-режима и лишних разрешений, ZIP-выравнивание APK на 16 КБ. `--abis` позволяет явно задать другие архитектуры; ARM64 обязателен. Для следующей загрузки в Play Console нужно увеличить `--version-code`. Это значение задаётся локальной сборкой; версии облачного EAS управляются отдельно, поэтому перед сменой способа сборки нужно согласовать следующий номер.

Артефакты и отчёт с SHA-256 сохраняются в новой папке `.release-builds/android-…`. Gradle init script подключает подпись только к этой команде. Обычный `gradlew assembleRelease` из шаблона Expo по-прежнему использует debug key — такой файл не является кандидатом для магазина.

Ключ, его публичный сертификат и пароли лежат в `.release-secrets`. Каталог исключён из Git и форматирования. В Windows доступ ограничен учётной записью создавшего процесс и владельцем рабочей папки; на POSIX каталог создаётся с режимом 0700. Пароли не передаются в аргументах процессов и не выводятся в журнал. Перед выпуском сохранить защищённую резервную копию этого каталога отдельно от компьютера. Не отправлять его в чат, Git или вместе с APK.

В новой карточке Google Play рекомендуется использовать Play App Signing: созданный ключ служит для загрузок AAB, а Google подписывает устанавливаемые магазином APK своим ключом. Поэтому локальный APK и версия из Play могут иметь разные подписи. Описание: [Android app signing](https://developer.android.com/studio/publish/app-signing).

Локальный APK также отличается подписью от вчерашнего debug APK. Если debug-версия уже установлена, сначала экспортировать её историю. Автоматически удалять установленное приложение ради смены подписи нельзя.

`--api-url` обязателен и встраивается в JS при сборке. Новый сервер ещё не опубликован на `ownday.vercel.app`; текущий кандидат предназначен прежде всего для проверки локального гостевого цикла. Подпись не подтверждает работу входа, синхронизации и напоминаний на устройстве. Для проверки аккаунта нужен совместимый тестовый сервер, затем отдельная сборка с его HTTPS-адресом.

## iOS

Версии сборочного окружения EAS закреплены: Node 22.22.2 и pnpm 10.15.0. Это сохраняет применение патча SQLite из pnpm-конфигурации. Нативные зависимости согласованы с Expo 57.0.22 / React Native 0.86.3; Metro Runtime 57.0.15 указан явно, чтобы новый Expo Router не получал старый автоматически установленный peer dependency. На актуальном облачном проходе успешно выполнены все 21 проверки Expo Doctor.

В `apps/mobile/eas.json` разделены профили:

| Профиль | Результат iOS | Требования |
| --- | --- | --- |
| `preview-simulator` | Самостоятельное приложение для симулятора | Expo; Mac для запуска |
| `development-simulator` | Клиент разработки для симулятора | Expo, Metro; Mac для запуска |
| `preview` | Сборка для зарегистрированных iPhone/iPad | Apple Developer, подписи и зарегистрированные устройства |
| `development` | Клиент разработки для зарегистрированных устройств | Apple Developer, Metro |
| `production` | Сборка для App Store / TestFlight | Apple Developer, App Store Connect и подписи |

Команды из `apps/mobile`:

```sh
eas whoami
eas project:info
eas build --platform ios --profile preview-simulator
# После подключения Apple Developer:
eas build --platform ios --profile preview
```

Сборка для симулятора не устанавливается на iPhone. Облачный EAS собирает нативный проект на macOS; локальный Windows-компьютер не запускает Xcode. См. [iOS Simulator](https://docs.expo.dev/build-reference/simulators/) и [internal distribution](https://docs.expo.dev/build/internal-distribution/).

В конфигурации EAS объявлен дополнительный target `OwndayWidget` с bundle ID `app.ownday.mobile.widget` и App Group `group.app.ownday.mobile`. При подключении Apple Developer потребуются подписи для приложения и виджета. Плагин создаёт сами нативные targets, entitlement и мост; объявление в `extra.eas` позволяет EAS узнать о виджете до генерации Xcode-проекта. См. [Expo app extensions](https://docs.expo.dev/build-reference/app-extensions/).

Apple Developer пока отсутствует. Пользователь может предоставить iPhone; Android-устройство сейчас не подключено. Для подписанного IPA через EAS нужно сначала оформить [Apple Developer](https://developer.apple.com/programs/enroll/), затем настроить сертификаты и устройство либо TestFlight. Подключение iPhone к Windows само по себе не создаёт подпись. Даже после успешной компиляции симулятора остаются нативный Apple-вход, серверный отзыв Apple при удалении аккаунта, доставка уведомлений и работа виджета на настоящем устройстве.

## Перед публикацией

Проверить установку/перезапуск без сети, дробные отметки и отмену, уведомления после закрытия, смену дня виджета, экспорт и сохранность истории при обновлении. На совместимом тестовом сервере проверить вход, два устройства, конфликты, выход и удаление аккаунта. Затем проверить миграцию копии действующих данных, окончательные документы магазина и рабочие ссылки поддержки/конфиденциальности. Эти шаги не заменяются успешной сборкой файла.
