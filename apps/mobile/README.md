# Ownday — «Живой дневник»

Главный экран подключён к локальной SQLite. Доступны создание и изменение привычек, утро/день/вечер, счётчики и минуты, точные дробные значения, пропуск и отмена, календарь, архив, поиск, сортировка, статистика, RU/EN, светлая и тёмная темы, экспорт. Данные гостя и очередь записываются одной транзакцией.

## Локальный просмотр

Из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm --filter '@ownday/mobile^...' build
pnpm --filter @ownday/mobile exec expo export --platform web --output-dir dist/web
node apps/mobile/preview.mjs
```

Открыть `http://127.0.0.1:8082`. Сервер выставляет заголовки изоляции, необходимые браузерному адаптеру SQLite. Это предварительный просмотр мобильного интерфейса: он не заменяет проверки iOS/Android. Данные этого интерфейса являются локальными пользовательскими данными, в отличие от отдельного `apps/design-lab` с помеченными демонстрационными сценариями.

Expo SQLite 57.0.3 обрезает длину синхронного ответа web worker до одного байта и измеряет тайм-аут количеством итераций CPU. Патч в `patches/` сохраняет полное 32-битное значение и проверяет прошедшее время; он применяется pnpm автоматически. Первое открытие SQLite асинхронное, чтобы worker успел загрузить WASM.

## Нативная сборка

Воспроизводимая сборка с отдельным upload key, APK/AAB и профилями iOS описана в [mobile-release.md](../../docs/mobile-release.md). Команда ниже создаёт только APK с тестовой подписью шаблона Expo.

```sh
pnpm --filter @ownday/mobile exec expo prebuild --platform android --no-install
cd apps/mobile/android
./gradlew :app:assembleRelease -PreactNativeArchitectures=arm64-v8a
```

Генерация нативных проектов также доступна отдельной командой `pnpm native:generate`. Не называть её `prebuild`: pnpm может выполнить такую команду автоматически перед `build`, удалив генерируемые файлы во время другой сборки. Нативная генерация и Gradle должны выполняться последовательно.

Нужны JDK 17, Android SDK 36, build tools 36.0.0, NDK 27.1.12297006 и CMake 3.22.1. Для локального просмотра сборка использует тестовую подпись шаблона Expo; выпуск в магазине требует отдельной подписи и проверки всех архитектур.

При запуске Java из Windows-приложения в MSIX может потребоваться собственный доступный каталог сокетов, например `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:\projects\habits\.java-tmp`. Это настройка окружения сборки, а не приложения.

## Аккаунт и синхронизация

В настройках нативного приложения подключены PKCE-вход, перенос гостя, синхронизация и выбор версии при конфликте. Сервер: `GET/POST /api/sync`; адрес задаётся `EXPO_PUBLIC_API_URL` до сборки. Данные без аккаунта остаются локальными. Для тестов использовать отдельный сервер и БД: новая серверная версия ещё не опубликована на ownday.vercel.app.

SQLite хранит подтверждённый сервером снимок и неподтверждённые операции отдельно. Положительные прибавления суммируются, абсолютные изменения требуют совпадения версии. При потере ответа повторяется тот же UUID; зависимые операции используют версию подтверждения предыдущей. Конфликт сохраняет локальное значение до получения ответа, удалённую версию и цепочку действий. История конфликтов включена в экспорт.

Перенос гостя транзакционный и сохраняет исходный профиль как резервную копию. После выхода создаётся отдельный чистый гостевой профиль. Выход без сети сохраняет отзыв токена в SecureStore и сразу изолирует профиль. Календарные настройки аккаунта пока меняются в веб-версии; синхронизация переносит часовой пояс и начало дня в мобильное приложение. Тема и язык выбираются локально.

Проверены две настоящие SQLite-базы через PostgreSQL и JSON-контракт: сумма прибавлений, потеря ответа, конфликт отмены, выбор версии и следующее действие после отмены. Собраны подписанные Android APK/AAB для ARM64/x86_64 и приложение с виджетом для iOS Simulator. Подключены локальные напоминания, виджеты v2 и восстановление прежних очередей через явный выбор. Старая AsyncStorage-очередь, кэш и данные виджетов не удаляются. Вход через браузер на устройстве, подписанный IPA для iPhone, реальная доставка, обновление старой установки и смена дня на лаунчере ещё требуют проверки.

Напоминания планируются до 60 событий на срок до 14 дней. Виджет хранит 31 день расписания и действия до их фиксации в SQLite. Устаревшие действия не перезаписывают журнал: в настройках появляется выбор. Подробности и ограничения — `docs/adr/0017-reminders-and-widget-delivery.md`.
